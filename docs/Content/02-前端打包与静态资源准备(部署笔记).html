02 · 前端打包与静态资源准备

把 Vue 源码变成 Nginx 能直接端出去的静态文件，并单独准备大图 / 音乐（不打进前端包）。

学习目标

学完本篇，你能够：

  1. 配置生产用的 .env.production（同域 API：/api/v1）
  2. 在本机执行 npm run build，理解产物在 docs/
  3. 确认 不打包 img/、Music/（由 Nginx 提供）
  4. 用项目脚本打出 frontend.zip 与 media.tar.gz，并上传到 ECS

前置条件

条件 说明
本机已安装 Node.js 18+ node -v / npm -v 可用
项目依赖已装过 在仓库根目录执行过 npm install 或 npm ci
01 篇完成 ECS 上已有 /var/www/cyinc，能 SSH 上传文件
理解路径 前端路由与 Vite base 都是 /myweb/

本机项目根目录（示例）：


D:\phpstudy\phpstudy_pro\WWW\gerenboke

为什么要「打包」？打完长什么样？

开发时 npm run dev 像「现炒现卖」：改代码立刻刷新。

上线需要「盒饭」：提前编译成浏览器能直接打开的 HTML/JS/CSS。

对本项目：


npm run build
    ↓
docs/                 ← 构建输出（不要手改里面的 hashed 文件名）
  index.html
  assets/             ← 带 hash 的 JS/CSS
  Content/            ← 博客文章 HTML（脚本会处理）
  data/               ← 导出的 JSON 等

刻意不打进包的：

  • img/（尤其 img/BA 大图库）
  • Music/

原因：体积巨大；ECS 上由 Nginx 用 alias 直接提供，构建更快、上传更小。

开关在 .env.production 的 VITE_BUNDLE_STATIC_MEDIA=0（ECS 推荐）。

详细操作步骤

步骤 1：准备 .env.production

在本机项目根目录（不是 backend/）：


cd D:\phpstudy\phpstudy_pro\WWW\gerenboke
copy .env.production.example .env.production
notepad .env.production

推荐内容（与仓库示例一致）：


# 与 ECS Nginx 同域，用相对路径，不要写死 http://127.0.0.1:8000
VITE_API_BASE_URL=/api/v1

# Twikoo 等按你实际填写；没有可留示例或空
VITE_TWIKOO_ENV_ID=https://cyinc-twikoo.netlify.app/.netlify/functions/twikoo

# 音乐同域：留空 = /myweb/Music/
VITE_MUSIC_BASE_URL=

# 0 = 不打包 img/Music（ECS + Nginx）；GitHub Pages 才需要改成 1
VITE_BUNDLE_STATIC_MEDIA=0

类比：环境变量像给程序设的「开关和路牌」。

VITE_API_BASE_URL=/api/v1 告诉前端：「请求接口时走当前网站下的 /api/v1」，这样浏览器访问 https://域名/myweb/ 时，API 自动变成 https://域名/api/v1，不会跨域。

注意：.env.production 已在 .gitignore，不要提交。

步骤 2：安装依赖并构建


cd D:\phpstudy\phpstudy_pro\WWW\gerenboke
npm ci
npm run build

命令含义：

  • npm ci：按 package-lock.json 干净安装（比 npm install 更适合发布前）
  • npm run build：实际会跑一串脚本（见 package.json），包括：

- 导出文章 JSON、生成缩略图、音乐列表等

- vite build --base /myweb/ ← base 必须是 /myweb/

- 生成站点文件与预渲染到 docs/

构建时若看到类似提示是正常的：


[vite] 生产构建不打包 img/Music（由 Nginx 同域提供）...

成功标志：


Test-Path docs\index.html
# 应为 True

Get-ChildItem docs\assets | Select-Object -First 5
# 应有 .js / .css 等文件

打开 docs/index.html，确认资源路径带 /myweb/，例如：


<script type="module" src="/myweb/assets/index-xxxxx.js"></script>

若写成 /assets/... 而没有 /myweb，说明 base 错了，检查是否用了错误的 build 命令。

步骤 3：用官方脚本打前端包（推荐）

仓库已提供 PowerShell 脚本：


cd D:\phpstudy\phpstudy_pro\WWW\gerenboke
.\deploy\scripts\pack-frontend.ps1

脚本会：

  1. 若无 .env.production 则从 example 复制
  2. 执行 npm run build
  3. 把 Content\*.html 拷进 docs\Content
  4. 把 docs\* 压成项目根目录的 frontend.zip

成功标志：根目录出现 frontend.zip，且控制台打印文章数量，例如：


Content articles: 12
Done: ...\frontend.zip

步骤 4：打包媒体（img / Music）

大图和音乐单独打包（Windows zip 容易把中文路径弄乱，所以用 tar.gz）：


.\deploy\scripts\pack-media.ps1

脚本会打包存在的 img/BA 与 Music/，生成 media.tar.gz。

成功标志：


Done: ...\media.tar.gz (xxx MB)

若本地没有 img/BA 或 Music，脚本会报错——那说明媒体本来就不在仓库里，需要你从备份拷回本机后再打。

步骤 5：上传到 ECS

把 你的ECS公网IP 换成真实 IP，用户用 deploy（或 root）：


# 上传前端包
scp frontend.zip deploy@你的ECS公网IP:/var/www/cyinc/

# 上传媒体包（体积大，耐心等待）
scp media.tar.gz deploy@你的ECS公网IP:/var/www/cyinc/

在 ECS 上解压：


ssh deploy@你的ECS公网IP

cd /var/www/cyinc

# 前端 → myweb/
mkdir -p myweb
cd myweb
unzip -o ../frontend.zip
cd ..

# 媒体 → 仓库根下的 img/、Music/
# 先备份旧目录（若有）再解压
rm -rf img/BA Music
tar -xzf media.tar.gz

# 抽查中文路径是否正常
ls img/BA/ | head
ls Music/ | head

含义：

  • unzip -o：覆盖解压到 myweb/
  • tar -xzf：解压 tar.gz，保留目录结构
  • Nginx 配置里会把 /myweb/img/ alias 到 /var/www/cyinc/img/（见 05 篇）

备选：rsync 直接同步 docs/（本机有 rsync + SSH 时）：


# Git Bash / WSL
npm run build
bash deploy/scripts/sync-frontend.sh deploy@你的ECS公网IP

该脚本把本机 docs/ 同步到 ECS 的 /var/www/cyinc/myweb/。

步骤 6：核对服务器文件树

在 ECS：


ls -la /var/www/cyinc/myweb/index.html
ls /var/www/cyinc/myweb/assets | head
ls /var/www/cyinc/myweb/Content | head
ls /var/www/cyinc/img /var/www/cyinc/Music

期望结构：


/var/www/cyinc/
├── myweb/
│   ├── index.html
│   ├── assets/
│   ├── Content/
│   └── data/          # 视构建结果而定
├── img/
│   └── BA/            # 大图
└── Music/

此时 Nginx 可能还没配好，浏览器暂时打不开很正常；本篇只要求文件就位。

检查点

  • [ ] .env.production 中 VITE_API_BASE_URL=/api/v1、VITE_BUNDLE_STATIC_MEDIA=0
  • [ ] docs/index.html 存在，资源路径含 /myweb/
  • [ ] ECS /var/www/cyinc/myweb/index.html 存在
  • [ ] ECS /var/www/cyinc/img 与 /var/www/cyinc/Music 内容正确（若站点需要）
  • [ ] docs/ 里没有整棵巨大的 img/BA（说明没误打包媒体）

本机快速确认是否误打包媒体：


Test-Path docs\img\BA
# 期望 False（ECS 模式）

Test-Path docs\Music
# 期望 False

常见问题与解决方案

Q1：页面能开，但图片 / 音乐全是 404

原因：前端包上去了，但 img/、Music/ 没上传，或 Nginx 的 alias 路径不对。

处理：

  1. 确认 ECS 上 ls /var/www/cyinc/img、ls /var/www/cyinc/Music 有内容
  2. 确认 Nginx 含有（05 篇会配）：

location ^~ /myweb/img/ {
    alias /var/www/cyinc/img/;
}
location ^~ /myweb/Music/ {
    alias /var/www/cyinc/Music/;
}
  1. 若中文文件名乱码：不要用 Windows 资源管理器随便 zip 媒体，改用 pack-media.ps1 生成的 media.tar.gz

Q2：打开 https://域名/myweb/ 白屏，控制台报 JS 404

原因：构建 base 不是 /myweb/，或文件没解压到 myweb/ 而是解压到了别的目录。

处理：


# 看 index.html 里的脚本路径是否带 /myweb/
head -n 30 /var/www/cyinc/myweb/index.html

# 确认 assets 真实存在
ls /var/www/cyinc/myweb/assets | head

本机重建时确认命令是 npm run build（内部已 --base /myweb/），不要误用 build:local（那是另一套 base）。

Q3：npm run build 很慢或 sharp / python 报错

原因：构建链会跑缩略图（sharp）和部分 Python 脚本（如 cursors）。

处理：

  1. 确保本机 npm ci 完整成功
  2. Python 相关：python --version 可用，或按报错安装依赖
  3. 若仅想先验证 Vite：可临时排查是哪一步脚本失败（看终端最后一条报错）；修好后再完整 npm run build
