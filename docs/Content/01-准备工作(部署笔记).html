01-准备工作(部署笔记) — 学习笔记。

01 · 准备工作

把「空服务器」变成「能跑 CYINC.LOG 的地基」：买机器、连上去、装好 Docker 和 Nginx。

学习目标

学完本篇，你能够：

  1. 购买并登录一台阿里云 ECS（Ubuntu 22.04）
  2. 用 SSH 安全连接服务器
  3. 把域名 A 记录解析到 ECS 公网 IP
  4. 安装 Docker、Nginx、Certbot，并创建部署目录 /var/www/cyinc

前置条件

在开始前请准备好：

需要什么 说明
阿里云账号 能买 ECS；有实名认证
域名（推荐） 如 example.com；国内 ECS 正式对外常需备案
本机终端 Windows 可用 PowerShell，或装 Git Bash / Windows Terminal
SSH 公钥（推荐） 比每次输密码更安全；没有也能先用密码登录

本机已有项目仓库（路径示例）：


D:\phpstudy\phpstudy_pro\WWW\gerenboke

详细操作步骤

步骤 1：购买 ECS

  1. 打开阿里云控制台 → 云服务器 ECS → 创建实例。
  2. 建议规格（够跑本站）：

- 地域：选离你用户近的（如华东）

- 镜像：Ubuntu 22.04 64 位

- 规格：2 vCPU / 2～4 GiB 内存

- 系统盘：40 GiB 及以上

- 带宽：按量或固定带宽均可（入门可先 3～5 Mbps）

  1. 设置 root / 自定义用户密码，或绑定 SSH 密钥对（更推荐）。
  2. 创建完成后，在实例列表记下 公网 IP，下文记作 你的ECS公网IP。

安全组（防火墙规则）必须放行：

端口 用途
22 SSH 登录
80 HTTP（证书申请、跳转 HTTPS）
443 HTTPS 正式访问

不要放行 8000（API）、3306（MySQL）、6379（Redis）到公网。

成功标志：控制台显示实例「运行中」，能看到公网 IP。

步骤 2：用 SSH 登录服务器

在本机 PowerShell 或终端执行（把 IP 换成你的）：


ssh root@你的ECS公网IP

逐行含义：

  • ssh：远程登录工具
  • root@...：以 root 用户连到那台机器
  • 第一次会问 Are you sure you want to continue connecting? → 输入 yes

若用密钥：


ssh -i C:\Users\你的用户名\.ssh\id_rsa root@你的ECS公网IP
  • -i：指定私钥文件路径

预期输出：出现类似 root@iZxxxxx:~# 的命令提示符，说明已进服务器。

步骤 3：域名解析（有域名时）

！！！注意：是有域名的时候

  1. 在域名服务商（阿里云 / Cloudflare 等）进入 DNS 解析。
  2. 添加 A 记录：
主机记录 记录类型 记录值
@ A 你的ECS公网IP
www A 你的ECS公网IP
  1. 等待几分钟到几十分钟生效。

在本机检查：


ping 你的域名.com

成功标志：能 ping 通，或至少解析出的 IP 等于 ECS 公网 IP。

（部分服务器禁 ping，解析正确即可。）

用 nslookup 更稳：


nslookup 你的域名.com

步骤 4：创建部署用户与目录（推荐）

长期用 root 跑业务不理想。创建专用用户 deploy：


# 创建用户 deploy，并给 sudo 权限（可选）
adduser deploy
usermod -aG sudo deploy

# 创建网站根目录，并交给 deploy
mkdir -p /var/www/cyinc
chown -R deploy:deploy /var/www/cyinc

这个是看你自己的网站文件夹是怎么样，注意区分

含义：

  • adduser deploy：新建系统用户
  • usermod -aG sudo deploy：允许用 sudo 执行管理命令
  • /var/www/cyinc：本站约定的「家」，后面所有文件都放这里

切换到 deploy：


su - deploy
cd /var/www/cyinc

步骤 5：克隆仓库到服务器

把 GitHub 地址换成你的真实仓库：


cd /var/www/cyinc
git clone https://github.com/你的用户名/gerenboke.git .

说明：

  • 末尾的 .：克隆到当前目录，而不是再套一层文件夹
  • 若仓库是私有的，需配置 Deploy Key 或 Personal Access Token

成功标志：


ls /var/www/cyinc

应能看到 backend/、deploy/、docker-compose.prod.yml、package.json 等。

若暂时不想在服务器装前端构建环境：可以只克隆代码跑后端，前端在 Windows 本机构建后上传（见 02 篇）。这是推荐做法。

步骤 6：一键安装 Docker / Nginx / Certbot

项目已提供初始化脚本：


cd /var/www/cyinc
sudo bash deploy/scripts/setup-server.sh

脚本会大致做这些事（见 deploy/scripts/setup-server.sh）：

  1. apt-get install 安装 git、nginx、certbot、python3-certbot-nginx、ufw
  2. 安装 Docker 与 docker-compose-plugin
  3. 确保 deploy 用户在 docker 组
  4. 创建 /var/www/cyinc/myweb
  5. 防火墙放行 SSH 与 Nginx

若脚本里的 REPO_URL 还是占位符，可先手动 git clone（上一步），再跑脚本装软件。

手动核对版本（脚本跑完后执行）：


docker --version
# 预期类似：Docker version 24.x.x 或更高

docker compose version
# 预期类似：Docker Compose version v2.x.x

nginx -v
# 预期：nginx version: nginx/1.18.x 或更高

certbot --version
# 预期：certbot 1.x 或 2.x

让当前用户免 sudo 使用 Docker（若提示 permission denied）：


sudo usermod -aG docker $USER
# 重新登录 SSH 后生效
exit
ssh deploy@你的ECS公网IP

步骤 7：（可选）本机装 Node / 仅用于本地构建

前端打包通常在 Windows 开发机完成，服务器不必装 Node。

本机检查：


node -v
# 建议 v18 或 v20+

npm -v

没有就从 https://nodejs.org 安装 LTS。

后端生产用 Docker 镜像内的 Python，服务器一般不必单独装 Python 跑 API；仅当你要在宿主机跑 set_admin_password.py 时，才需要：


python3 --version
# Ubuntu 22.04 自带多为 3.10+

检查点

全部通过再进入下一篇：

  • [ ] SSH 能稳定登录 ECS
  • [ ] docker --version 与 docker compose version 正常
  • [ ] nginx -v 正常
  • [ ] 目录 /var/www/cyinc 存在且属主为 deploy
  • [ ] 仓库代码已在 /var/www/cyinc（或至少 deploy/、backend/、docker-compose.prod.yml 在）
  • [ ] 安全组仅开放 22/80/443
  • [ ] （有域名）A 记录已指向 ECS

快速自检命令：


whoami
# 预期：deploy（或你创建的部署用户）

pwd
# 建议在：/var/www/cyinc

ls backend/Dockerfile docker-compose.prod.yml deploy/nginx.conf.example
# 三个文件都应存在

常见问题与解决方案

Q1：ssh: connect to host ... port 22: Connection timed out

可能原因：安全组没开 22；本机网络限制；IP 填错。

处理：

  1. 阿里云控制台 → 安全组 → 入方向添加 TCP 22
  2. 确认实例公网 IP 是否变更（停机再开会变的情况较少，但按量带宽注意）
  3. 用控制台「远程连接 / Workbench」验证机器本身是否正常

Q2：Permission denied (publickey) 或一直要密码却登不进

可能原因：只用密钥登录但本机没带对私钥；或密码输错次数过多。

处理：


# 明确指定私钥
ssh -i ~/.ssh/id_rsa root@你的ECS公网IP

# Windows 路径示例
ssh -i $env:USERPROFILE\.ssh\id_rsa root@你的ECS公网IP

仍不行：在阿里云控制台重置实例密码，或绑定新密钥对后重试。

Q3：docker: command not found 或 docker compose 不可用

处理：


curl -fsSL https://get.docker.com | sudo sh
sudo apt-get update
sudo apt-get install -y docker-compose-plugin
sudo systemctl enable --now docker
docker compose version

若只有旧版 docker-compose（带连字符），后续命令写成：


docker-compose -f docker-compose.prod.yml ps

本仓库的 deploy/scripts/deploy.sh 两种写法都支持。
