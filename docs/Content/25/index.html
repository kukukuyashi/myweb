这是个什么项目？

「陈皮有多陈」是一个围绕新会陈皮做的展示 + AI 鉴定小站，参加第八届传智杯。核心卖点：拍一张陈皮照片，AI 帮你估产地、年份、等级、参考价；另外还有溯源查询、市场指数、百科、地图找产区、养生搭配等页面。

和本博客（Vue 静态站）完全不同 — 这是传统多页 Web + Python 后端，需要本地跑 Flask 服务。

页面一览

路由功能

后端：一个 app.py 走天下

没有拆微服务，所有路由、AI 逻辑、模拟数据都在 app.py（约 900+ 行）。比赛周期短这样最快，但长期维护会累 — 以后可以拆 Blueprint 或 service 层。

主要 API：

  • POST /api/analyze — 上传图片，返回鉴定 JSON
  • POST /api/traceability/query — 查溯源码
  • GET /api/market/index — 市场数据
  • POST /api/health/recipe — 养生搭配

AI 鉴定流程（通俗版）

用户选图 / 拍照
    ↓
前端 FormData POST 到 /api/analyze
    ↓
后端 Pillow 缩图（最大 1024px、转 JPEG）
    ↓
转 base64 塞进多模态 prompt
    ↓
OpenAI SDK → 阿里云 DashScope 兼容接口 → qwen3-vl-plus
    ↓
从回复里正则抠 JSON → 填默认值 → 返回前端渲染报告
    ↓
（失败则降级到本地模拟规则，保证 demo 不挂）
💡 用 OpenAI 官方 SDK 连 DashScope「兼容模式」URL，代码写法和其他 vision API 几乎一样，换模型成本低。

降级策略（比赛现场很重要）

免费 API 可能超时、限流、断网。项目做了四层兜底：

  1. OpenAI SDK 调 Qwen（重试 3 次）
  2. 失败则 raw requests 再试
  3. 再失败走 _analyze_simulation() — 按产区、香气关键词随机但「像真的」
  4. JSON 解析失败也回模拟数据

答辩时网络抽风不至于白屏 — 这是 demo 项目和生产系统的差别。

前端：没有 Vue，但页面不简陋

每页一个 HTML 模板，公共头尾用 Jinja {% include 'partials/header.html' %}。样式在 static/css/yaopu-theme.css — 「广府药铺」风：纸色背景、 serif 字体、陈皮配色。

ai-center.html 最大：内联了摄像头 getUserMedia、进度条、结果卡片渲染。地图页 search.html 把 Leaflet + 地标 JSON 写在一文件里，像一个小型 SPA。

本地怎么跑？

cd Web(Release)
# Windows 可直接双击 start.bat
pip install -r requirements.txt
python app.py
# 浏览器打开 http://127.0.0.1:5000

requirements.txt 核心：Flask、Flask-CORS、Pillow、openai、requests。

安全提醒（写进笔记给自己看）

演示版曾在代码里硬编码 API Key — 本地比赛可以，上传 GitHub 必须改成环境变量 os.environ['QWEN_API_KEY']，否则 key 泄露会被刷额度。

溯源、市场数据是预设模拟，页面应标明「演示数据」，别让用户当成真实交易依据。

如果重做，我会改什么？

  • API Key 进 .env，python-dotenv 读取
  • app.py 拆成 routes/ + services/analyzer.py
  • 前端公共 JS 抽成 static/js/common.js，别每页复制粘贴
  • 真溯源再接数据库，别写死在 dict 里

小结

陈皮项目证明：不一定非要 Vue/React 才能做完整 Web。Flask + 模板 + 一个 vision API，几天能搓出能演示的 AI 应用。和博客项目互补 — 一个练前端工程化，一个练后端 + AI 接入。

两个项目都留在硬盘里，正好对应「静态展示站」和「动态 AI 小站」两种路线，以后选题心里也有数。

静态预览供搜索引擎阅读；交互版由 Vue 加载后替换本区域。
