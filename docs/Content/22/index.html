博客音乐室：GitHub Pages 上播 FLAC

日期：2026-06-14
音乐室：/music

想实现什么？

博客除了看文章，还想挂一个自己的歌单：葬送のフリーレン OST、SANABI、动漫 ED 之类。要求：

  • 在音乐室点歌，底部栏持续播放
  • 切到首页、关于页，音乐不要停、不要重头播
  • GitHub Pages 纯静态，不能走后端流媒体

架构：三件套

模块作用
Music.vue音乐室页面：曲目表格、选中播放
MusicPlayer.vue底部固定播放器：进度条、音量、暂停
Pinia music store跨页面保存当前歌曲、播放状态、进度

音频文件放在项目根目录 Music/，构建时整夹复制到 docs/Music/，和文章 HTML 一样当静态资源发出去。

曲目列表怎么维护？

手写 38 行路径太容易错（日文文件夹名、空格、FLAC 后缀）。现在用脚本自动扫盘：

node scripts/generate-music-tracks.mjs

输出 src/data/musicTracks.js，Music.vue 直接 import。往 Music/ 加专辑后 rebuild 即可。

开发环境 Vite 还挂了一个中间件，npm run dev 时直接读本地 Music/，不用每次 build 复制几百 MB。

FLAC 在浏览器里能播吗？

现代 Chrome / Edge / Firefox 大多支持 FLAC；Safari 部分版本不支持。个人博客场景够用了，真要在 iPhone 上完美兼容可以额外备一份 MP3。

路径里有中文、日文、空格时，前端 URL 必须 encodeURI，否则 404：

function musicUrl(relativePath) {
  const base = import.meta.env.BASE_URL || '/'
  return base + encodeURI(relativePath.replace(/^\//, ''))
}

踩坑 1：进度条拖不动

一开始用 v-model 绑进度条，和 timeupdate 事件打架，一拖就弹回去。改法：

  • 拖动时用 isDragging 标记，暂停同步 store
  • pointerup 时再写 audio.currentTime
  • 等 canplay 事件后再 seek，避免 metadata 没加载完

踩坑 2：换页面音乐重头播

原因：每个页面都写了一个 <MusicPlayer />。Vue Router 切页时旧组件销毁、新组件重建，onMounted 里又 loadSong()，等于重新加载音频。

修法：

  1. 把 MusicPlayer 挪到 App.vue，全站只挂载一次
  2. 用 window.globalAudio 共享同一个 Audio 实例
  3. 换歌时才改 src；同歌切页只同步 UI，不 reload
💡 全局播放器是 SPA 的常见模式 — 网易云网页版也是一套 player 走天下。

踩坑 3：仓库体积

一张 FLAC 专辑就一百多 MB，git 仓库会胖。权衡之后：

  • 个人站可以接受（GitHub 单文件建议 < 100MB，整 repo 免费额度够用）
  • 若以后太大，可把 Music/ 放 CDN，用 VITE_MUSIC_BASE_URL 指过去

播放状态怎么记住？

Pinia + sessionStorage：刷新页面可以恢复当前歌和进度；关浏览器 tab 后清掉，避免下次打开突然外放。

小结

音乐室不神秘：静态 MP3/FLAC + HTML5 Audio + 全局状态。难点在细节 — URL 编码、seek 时机、组件生命周期。修完换页重播之后，终于可以在写 Agent 笔记时后台循环芙莉莲 OST 了。

静态预览供搜索引擎阅读；交互版由 Vue 加载后替换本区域。
