为什么要重构？

最早这个站是纯静态 HTML：每篇文章一个文件，改导航要动好多页，样式也不统一。后来学了 Vue3，就想把它升级成「能维护的博客」而不是「一堆散文件」。

目标很简单：

  • 免费托管 — 继续用 GitHub Pages，不额外买服务器
  • 好改 — 文章列表、分类、标签集中管理
  • 能扩展 — 留言板、音乐室、关于页以后都能加
💡 个人博客不需要一上来就搞 SSR / 数据库，静态站 + 第三方服务对个人来说性价比最高。

目录结构（核心）

gerenboke/
├── Content/          # 文章 HTML 正文（构建时复制到 docs）
├── Music/            # 音乐室音频（构建时复制）
├── img/              # 图片资源
├── src/
│   ├── views/        # 页面：Home、Content、Music、About…
│   ├── components/   # NavBar、MusicPlayer、StickerWall…
│   ├── data/
│   │   └── posts.js  # 文章目录（标题、日期、分类、文件名）
│   └── router/
├── docs/             # 构建产物，GitHub Pages 实际发布这里
└── vite.config.js    # base: '/myweb/' 很重要

发新文章只需两步：

  1. 在 Content/ 放一篇 HTML
  2. 在 src/data/posts.js 加一条记录（id、title、date、category、tags、file）

GitHub Pages 必踩的两个坑

1. 子路径 base

仓库页地址是 username.github.io/仓库名/，不是根域名。Vite 必须设：

export default defineConfig({
  base: '/myweb/',
  build: { outDir: 'docs' }
})

否则 JS、CSS、图片全部 404。

2. SPA 刷新 404

Vue Router 用的是 History 模式，直接访问 /myweb/content/19 时，GitHub Pages 找不到这个物理文件。解决办法：在 docs/404.html 里写跳转逻辑，或构建脚本生成 fallback，让任意路径都回到 index.html 再由前端路由接管。

文章页怎么渲染 HTML？

正文不写在 Vue 组件里，而是独立的 HTML 片段。文章页用 fetch 拉取 Content/xxx.html，再 v-html 插入，最后用 Prism 做代码高亮。

好处：写笔记可以用任意编辑器；坏处：要注意 XSS — 只放自己写的内容，别引入不可信 HTML。
