鼠标动画光标：从 PNG 序列到 Chrome 兼容

日期：2026-06-29

一、问题从哪来

上一篇《自定义鼠标样式与点击涟漪效果》里，光标是用 CSS cursor: url(...gif) 挂上去的。素材放在 public/cursors/，构建后路径是 /myweb/cursors/normal.gif 这类。

Firefox 里 GIF 光标能正常动；Chrome / Edge 往往只显示 GIF 第一帧，看起来就像鼠标「冻住了」。这不是素材坏了，是浏览器对 CSS 自定义光标的实现限制。

二、素材：img/Mouse animation/

项目里有一套「鼠标计划」动画资源，目录结构大致如下：

子目录 用途 帧数（PNG）
普通（第二版）/ 默认指针 130
交互（第二版）/ 链接、按钮 94
文本/ 输入框 140
加载/ 路由切换等待 45

根目录还有合成好的 普通.gif、交互.gif 等，但 PNG 序列帧数更多、画质更高，生成脚本优先读子目录里的 PNG。

浏览器光标尺寸建议 64×64，再大容易被忽略。脚本会把 240×240 的 PNG 用 LANCZOS 缩到 64×64，再合成 GIF。

三、生成脚本 scripts/generate-cursors.py

核心逻辑：按文件名里的序号排序 PNG → 逐帧缩放 → 写出 GIF。


MAPPING = {
    '普通（第二版）': 'normal.gif',
    '交互（第二版）': 'pointer.gif',
    '文本': 'text.gif',
    '加载': 'busy.gif',
}

输出到 public/cursors/，Vite 构建时会复制到 docs/cursors/。

本地单独生成：


npm run cursors:generate

npm run build 也会自动跑这一步，避免忘了更新光标。

依赖：Python 3 + Pillow（pip install Pillow）。

四、Chrome 兼容：useAnimatedCursor.js

思路：隐藏系统光标，用 fixed 定位的 <img> 跟着鼠标走。<img> 里的 GIF 在各浏览器都能播动画。

  1. mousemove 里用 requestAnimationFrame 更新位置（热点偏移 8, 8）。
  2. elementFromPoint 判断当前元素，切换四种 GIF：

- normal — 默认

- pointer — 链接、按钮等

- text — input / textarea

- busy — html 带 cursor-busy 时（路由切换）

  1. 禁用元素上隐藏自定义层，保留系统 not-allowed。
  2. prefers-reduced-motion: reduce 或 (pointer: coarse) 时不启用，回退 CSS 静态光标。

在 App.vue 里一行挂载：


useAnimatedCursor()

CSS 侧给 html.has-animated-cursor 加 cursor: none，避免双光标。

五、和路由过渡的配合

useRouteTransition.js 在路由 beforeEach 时给 document.documentElement 加 cursor-busy，afterEach 延迟 300ms 去掉。叠加层通过 MutationObserver 监听 class 变化，自动切到 busy.gif。

六、文件一览

路径 作用
img/Mouse animation/ 原始 PNG / GIF 素材
scripts/generate-cursors.py PNG → 64×64 GIF
public/cursors/*.gif 站点使用的光标
src/composables/useAnimatedCursor.js 跟随鼠标的 GIF 层
src/styles/_base.css has-animated-cursor、涟漪等样式

七、踩坑小结

  1. CSS GIF 光标在 Chrome 不动 → 用 JS 叠加层，不要只靠 cursor: url()。
  2. 路径要带 base → 项目 base: '/myweb/'，JS 里用 import.meta.env.BASE_URL + 'cursors/...'。
  3. PNG 比根目录 GIF 更适合做源 → 帧数多；Pillow 写 GIF 时会合并完全相同的相邻帧，属正常现象。
  4. 触控设备别强上 → (pointer: fine) 检测后再启用，避免平板上一根看不见的光标。
