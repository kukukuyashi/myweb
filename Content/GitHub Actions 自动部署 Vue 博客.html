GitHub Actions 自动部署 Vue 博客

日期：2026-06-13
工作流文件：.github/workflows/deploy.yml
发布地址：https://kukukuyashi.github.io/myweb/

最终效果

每次把代码 git push 到 main 分支，GitHub 会自动：

  1. 拉取仓库代码
  2. 安装 Node 依赖
  3. 执行 npm run build
  4. 把 docs/ 文件夹发布到 gh-pages 分支

你本地不用手动上传，改完 push 等一两分钟就能在线上看到。

整体流程图（文字版）

你改代码 → push main
    ↓
GitHub Actions 触发
    ↓
npm install → npm run build
    ↓
生成 docs/（HTML + JS + Content + Music + img）
    ↓
peaceiris/actions-gh-pages 推到 gh-pages 分支
    ↓
GitHub Pages 从 gh-pages 提供网站

工作流文件详解

name: Deploy Vue3 Project

on:
  push:
    branches: [ main ]

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    permissions:
      contents: write
      pages: write
      id-token: write
    steps:
    - uses: actions/checkout@v4

    - name: Set up Node.js
      uses: actions/setup-node@v4
      with:
        node-version: '20.x'
        cache: 'npm'

    - name: Install dependencies
      run: npm install

    - name: Build project
      run: npm run build
      env:
        VITE_TWIKOO_ENV_ID: https://cyinc-twikoo.netlify.app/.netlify/functions/twikoo

    - name: Deploy to GitHub Pages
      uses: peaceiris/actions-gh-pages@v4
      with:
        github_token: ${{ secrets.GITHUB_TOKEN }}
        publish_dir: ./docs
        publish_branch: gh-pages
        force_orphan: true

逐段解释

配置含义
on.push.branches: [main]只有推 main 才部署，避免误触
permissions允许 Action 写仓库（推 gh-pages 需要）
cache: 'npm'缓存 node_modules，第二次构建更快
npm run build本地同一套命令，保证 dev / CI 一致
VITE_TWIKOO_ENV_IDCI 没有 .env.local，留言板地址在这里注入
publish_dir: ./docsVite 构建输出目录
force_orphan: truegh-pages 分支只保留最新一次构建，历史不会膨胀

build 脚本里还做了什么？

package.json 的 build 不是单纯 vite build：

"build": "node scripts/generate-about-gallery.mjs && node scripts/generate-music-tracks.mjs && vite build --base /myweb/ && node scripts/generate-site-files.mjs docs"
  • generate-about-gallery — 扫描 img/关于/ 生成贴纸墙数据
  • generate-music-tracks — 扫描 Music/ 生成音乐室曲目表
  • vite build — 打包 Vue，vite-plugin-static-copy 复制 Content / img / Music
  • generate-site-files — 生成 RSS、sitemap、robots.txt
💡 构建前跑脚本 = 「把磁盘上的资源变成前端能 import 的数据」，这样新增图片/歌曲不用手改 JS。

GitHub 仓库还要设什么？

  1. 打开仓库 Settings → Pages
  2. Source 选 Deploy from a branch
  3. Branch 选 gh-pages，目录 / (root)
  4. 保存后等 DNS 生效（通常 1～3 分钟）

第一次 push 后如果 Pages 还是 404，多半是 gh-pages 还没生成，去 Actions 页看 workflow 是否绿勾。

环境变量怎么管理？

变量放哪里说明
Twikoo envIdCI 的 env: 块是公开 API 地址，不是密钥，打进前端 bundle 正常
API 密钥GitHub Secrets真正秘密的才放 Secrets，本博客前端静态站目前不需要
本地开发.env.local已 gitignore，Twikoo 本地可自建 env 文件

常见故障

现象可能原因处理
Actions 红叉依赖安装失败 / 构建报错点进 log 看哪一步挂了，本地先 npm run build 复现
网站还是旧版浏览器缓存 / CDN硬刷新 Ctrl+F5，或无痕窗口打开
留言板加载失败CI 没注入 envId检查 deploy.yml 的 VITE_TWIKOO_ENV_ID
音乐 404Music 没进仓库或路径错确认 git 跟踪了 Music 文件夹，且 build 有 static-copy

小结

自动部署的价值不只是「省事」，更是保证线上和 build 脚本一致。只要本地 npm run build 能过，push 之后线上就应该一样 — 这是个人项目最稳的发布方式。
